## Question 264

- **Correct answer(s)**: `C, D, E`

### Question

A company runs a fleet of Amazon EC2 instances in a VPC. The company's employees remotely access
the EC2 instances by using the Remote Desktop Protocol (RDP). The company wants to collect
metrics about how many RDP sessions the employees initiate every day. Which combination of steps
will meet this requirement? (Select THREE.)

### Options

- **A.** Create an Amazon EventBridge rule that reacts to EC2 Instance State-change Notification events.
- **B.** Create an Amazon CloudWatch Logs log group. Specify the log group as a target for the
EventBridge rule.
- **C.** `[CORRECT]` Create a flow log in VPC Flow Logs.
- **D.** `[CORRECT]` Create an Amazon CloudWatch Logs log group. Specify the log group as a destination for the flow
log.
- **E.** `[CORRECT]` Create a log group metric filter.
- **F.** Create a log group subscription filter. Use EventBridge as the destination.

### Explanation

VPC Flow Logs capture network traffic metadata including destination ports, so creating a flow log (C) that captures TCP port 3389 (RDP) traffic, publishing it to a CloudWatch Logs log group (D), and then creating a metric filter (E) on that log group to count connections to port 3389 is the correct approach to count daily RDP sessions. EventBridge reacts to state-change events (A/B) which would track instance starts, not RDP sessions. A subscription filter (F) with EventBridge as destination is used to stream logs elsewhere, not to create metrics.

### Question

A DevOps engineer used an AWS CloudFormation custom resource to set up AD Connector. The AWS

Lambda function ran and created AD Connector, but CloudFormation is not transitioning from
CREATE_IN_PROGRESS to CREATE_COMPLETE. Which action should the engineer take to resolve this
issue?

### Options

- **A.** Ensure the Lambda function code has exited successfully.
- **B.** `[CORRECT]` Ensure the Lambda function code returns a response to the pre-signed URL.
- **C.** Ensure the Lambda function IAM role has cloudformation:UpdateStack permissions for the stack
ARN.
- **D.** Ensure the Lambda function IAM role has ds:ConnectDirectory permissions for the AWS account.

### Explanation

CloudFormation custom resources backed by Lambda require the Lambda function to send a response back to a pre-signed S3 URL provided in the event object. This response must include the Status (SUCCESS or FAILED) and the StackId, RequestId, LogicalResourceId, and PhysicalResourceId fields. If the Lambda function runs successfully but does not send this response to the pre-signed URL, CloudFormation will remain stuck in CREATE_IN_PROGRESS until it times out. The question describes exactly this scenario: the function ran and created the resource but CloudFormation never received the callback signal.

### Question

A company has a web application that is hosted on Amazon EC2 instances. The company is deploying
the application into multiple AWS Regions. The application consists of dynamic content such as
WebSocket-based real-time product updates. The company uses Amazon Route 53 to manage all
DNS records. Which solution will provide multi-Region access to the application with the LEAST
latency?

### Options

- **A.** `[CORRECT]` Deploy an Application Load Balancer (ALB) in front of the EC2 instances in each Region. Create a
Route 53 A record with a latency-based routing policy. Add IP addresses of the ALBs as the value of
the record.
- **B.** Deploy an Application Load Balancer (ALB) in front of the EC2 instances in each Region. Deploy an
Amazon CloudFront distribution with an origin group that contains the ALBs as origins. Create a
Route 53 alias record that points to the CloudFront distribution's DNS address.
- **C.** Deploy a Network Load Balancer (NLB) in front of the EC2 instances in each Region. Create a Route
53 A record with a multivalue answer routing policy. Add IP addresses of the NLBs as the value of the
record.
- **D.** Deploy a Network Load Balancer (NLB) in front of the EC2 instances in each Region. Deploy an
AWS Global Accelerator standard accelerator with an endpoint group for each NLB. Create a Route 53
alias record that points to the accelerator's DNS address.

### Explanation

The correct answer is D. AWS Global Accelerator with a standard accelerator routes traffic over the AWS global network backbone rather than the public internet, providing significantly lower and more consistent latency for multi-Region deployments. NLBs are ideal for WebSocket-based real-time applications due to their TCP-level load balancing. Global Accelerator also performs health checks and automatically routes around failures. Option A is technically incorrect because ALB IP addresses are dynamic and cannot be reliably added as static A record values. Option B (CloudFront) is better suited for cacheable static content rather than dynamic WebSocket connections. Option C with multivalue routing simply returns multiple IPs and does not optimize the network path.

### Question

A company has deployed a new REST API by using Amazon API Gateway. The company uses the API
to access confidential data. The API must be accessed from only specific VPCs in the company. Which
solution will meet these requirements?

### Options

- **A.** `[CORRECT]` Create and attach a resource policy to the API Gateway API. Configure the resource policy to allow
only the specific VPC IDs.
- **B.** Add a security group to the API Gateway API. Configure the inbound rules to allow only the
specific VPC IP address ranges.
- **C.** Create and attach an IAM role to the API Gateway API. Configure the IAM role to allow only the
specific VPC IDs.
- **D.** Add an ACL to the API Gateway API. Configure the outbound rules to allow only the specific VPC IP
address ranges.

### Explanation

To restrict API Gateway access to specific VPCs, you use a resource-based policy attached directly to the API. The resource policy can include conditions using the `aws:SourceVpc` or `aws:SourceVpce` condition keys to allow requests only from specified VPC IDs. Options B and D are incorrect because API Gateway does not support security groups or ACLs directly. Option C is incorrect because IAM roles are assumed by principals to gain permissions, not attached to APIs to restrict access by VPC.

will meet these requirements?

Option A (IAM Identity Center) could work but requires manually assigning each new account, making it less automated. Option C (SCP) cannot grant permissions — SCPs only restrict them. ### Question

A company has a search application that has a web interface. The company uses Amazon CloudFront,
Application Load Balancers (ALBs), and Amazon EC2 instances in an Auto Scaling group with a desired
capacity of 3. The company uses prebaked AMIs. The application starts in 1 minute. The application
queries an Amazon OpenSearch Service cluster. The application is deployed to multiple Availability
Zones. Because of compliance requirements, the application needs to have a disaster recovery (DR)
environment in a separate AWS Region. The company wants to minimize the ongoing cost of the DR
environment and requires an RTO and an RPO of under 30 minutes. The company has created an ALB
in the DR Region. Which solution will meet these requirements?

### Options

- **A.** `[CORRECT]` Add the new ALB as an origin in the CloudFront distribution. Configure origin failover functionality.
Copy the AMI to the DR Region. Create a launch template and an Auto Scaling group with a desired
capacity of 0 in the DR Region. Create a new OpenSearch Service cluster in the DR Region. Set up
cross-cluster replication for the cluster.
- **B.** Create a new CloudFront distribution in the DR Region and add the new ALB as an origin. Use
Amazon Route 53 DNS for Regional failover. Copy the AMI to the DR Region. Create a launch
template and an Auto Scaling group with a desired capacity of 0 in the DR Region. Reconfigure the
OpenSearch Service cluster as a Multi-AZ with Standby deployment. Ensure that the standby nodes
are in the DR Region.
- **C.** Create a new CloudFront distribution in the DR Region and add the new ALB as an origin. Use
Amazon Route 53 DNS for Regional failover. Copy the AMI to the DR Region. Create a launch
template and an Auto Scaling group with a desired capacity of 3 in the DR Region. Reconfigure the
OpenSearch Service cluster as a Multi-AZ with Standby deployment. Ensure that the standby nodes
are in the DR Region.
- **D.** Add the new ALB as an origin in the CloudFront distribution. Configure origin failover functionality.
Copy the AMI to the DR Region. Create a launch template and an Auto Scaling group with a desired

capacity of 3 in the DR Region. Create a new OpenSearch Service cluster in the DR Region. Set up
cross-cluster replication for the cluster.

### Explanation

Option A correctly implements a pilot light DR strategy. CloudFront origin failover with a single distribution is valid for cross-region DR. Setting Auto Scaling desired capacity to 0 minimizes ongoing cost while still allowing rapid scale-up within 30 minutes (AMI starts in 1 minute, so scaling from 0 to 3 is well within RTO). Cross-cluster replication for OpenSearch Service satisfies the RPO requirement. Option B/C are incorrect because CloudFront is a global service and you don't create separate regional distributions for DR; Route 53 DNS failover is not needed when CloudFront origin failover can handle it. Option D is incorrect because it keeps desired capacity at 3 in the DR region, increasing ongoing costs unnecessarily. Option C also keeps desired capacity at 3, and Multi-AZ with Standby for OpenSearch does not span across regions.

## Question 271

- **Correct answer(s)**: `A`
- **Domain**: Resilient Cloud (see [`synthesis/03-resilient-cloud-solutions.md`](../studyguides/03-resilient-cloud-solutions.md))
- **Multi-answer**: No

### Question

A DevOps team operates an integration service that runs on an Amazon EC2 instance. The DevOps
team uses Amazon Route 53 to manage the integration service's domain name by using a simple
routing record. The integration service is stateful and uses Amazon Elastic File System (Amazon EFS)
for data storage and state storage. The integration service does not support load balancing between
multiple nodes. The DevOps team deploys the integration service on a new EC2 instance as a warm
standby to reduce the mean time to recovery. The DevOps team wants the integration service to
automatically fail over to the standby EC2 instance. Which solution will meet these requirements?

### Options

- **A.** `[CORRECT]` Update the existing Route 53 DNS record's routing policy to weighted. Set the existing DNS
record's weighting to 100. For the same domain, add a new DNS record that points to the standby
EC2 instance. Set the new DNS record's weighting to 0. Associate an application health check with
each record.
- **B.** Update the existing Route 53 DNS record's routing policy to weighted. Set the existing DNS
record's weighting to 99. For the same domain, add a new DNS record that points to the standby EC2
instance. Set the new DNS record's weighting to 1. Associate an application health check with each
record.
- **C.** Create an Application Load Balancer (ALB). Update the existing Route 53 record to point to the
ALB. Create a target group for each EC2 instance. Configure an application health check on each
target group. Associate both target groups with the same ALB listener. Set the primary target group's
weighting to 100. Set the standby target group's weighting to 0.
- **D.** Create an Application Load Balancer (ALB). Update the existing Route 53 record to point to the
ALB. Create a target group for each EC2 instance. Configure an application health check on each
target group. Associate both target groups with the same ALB listener. Set the primary target group's
weighting to 99. Set the standby target group's weighting to 1.

### Explanation

The requirement is warm standby failover with no load balancing between nodes (stateful service). Route 53 weighted routing with weights 100/0 achieves active/standby behavior: the primary receives 100% of traffic while the standby receives 0%. When a health check fails on the primary record, Route 53 automatically routes traffic to the standby record. Option B (99/1) would send some traffic to standby even when primary is healthy, violating the no-load-balancing requirement. Options C and D use an ALB with weighted target groups, but ALB weighted target groups don't support automatic failover based on health checks in the same way — when a target group weight is 0, it receives no traffic regardless of health, and ALB doesn't automatically redistribute weight on failure. Route 53 weighted routing with health checks natively supports this failover pattern when one record's weight is non-zero (even 0-weight standby records receive traffic when all non-zero records are unhealthy), making Option A the correct solution.

### Question

A company has a guideline that every Amazon EC2 instance must be launched from an AMI that the
company's security team produces. Every month, the security team sends an email message with the
latest approved AMIs to all the development teams. The development teams use AWS
CloudFormation to deploy their applications. When developers launch a new service, they have to

search their email for the latest AMIs that the security department sent. A DevOps engineer wants to
automate the process that the security team uses to provide the AMI IDs to the development teams.
What is the MOST scalable solution that meets these requirements?

### Options

- **A.** Direct the security team to use CloudFormation to create new versions of the AMIs and to list the
AMI ARNs in an encrypted Amazon S3 object as part of the stack's Outputs section. Instruct the
developers to use a cross-stack reference to load the encrypted S3 object and obtain the most recent
AMI ARNs.
- **B.** Direct the security team to use a CloudFormation stack to create an AWS CodePipeline pipeline
that builds new AMIs and places the latest AMI ARNs in an encrypted Amazon S3 object as part of
the pipeline output. Instruct the developers to use a cross-stack reference within their own
CloudFormation template to obtain the S3 object location and the most recent AMI ARNs.
- **C.** `[CORRECT]` Direct the security team to use Amazon EC2 Image Builder to create new AMIs and to place the
AMI ARNs as parameters in AWS Systems Manager Parameter Store. Instruct the developers to
specify a parameter of type SSM in their CloudFormation stack to obtain the most recent AMI ARNs

- **D.** Direct the security team to use Amazon EC2 Image Builder to create new AMIs and to create an

Option C is the most scalable and automated solution. EC2 Image Builder automates the AMI creation process, and storing AMI ARNs in AWS Systems Manager Parameter Store allows CloudFormation templates to reference them directly using the SSM parameter type. This eliminates manual email communication, and when the security team updates the SSM parameter with a new AMI ID, CloudFormation stacks automatically use the latest value on the next deployment without any developer intervention. Options A and B introduce unnecessary complexity with S3 objects and cross-stack references, and Option D requires developers to write Lambda functions, adding operational overhead.
